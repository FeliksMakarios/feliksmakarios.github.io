Apple Foundation Model di MacBook M1

macOS 27 membawa model bahasa on-device milik Apple beserta perintah fm serve yang menyediakan API mirip OpenAI. Saya membuat GUI chat kecil bernama ChatAFM untuk mencobanya di MacBook M1, lalu mencatat apa saja yang bisa dan belum bisa diandalkan dari model ini.

01Apa Itu Apple Foundation Model dan fm serve

Apple Foundation Model adalah model bahasa yang menjadi dasar Apple Intelligence. Model ini berjalan langsung di perangkat, jadi prompt dan jawabannya tidak dikirim ke server mana pun. Pengembang aplikasi biasanya mengaksesnya lewat framework Foundation Models di Swift.

Di macOS 27, Apple juga menyertakan alat baris perintah fm di /usr/bin/fm. Salah satu subperintahnya, fm serve, menjalankan server lokal yang kompatibel dengan API Chat Completions milik OpenAI. Artinya, model on-device ini bisa dipanggil dengan cara yang sama seperti memanggil API model bahasa di cloud, cukup lewat HTTP ke 127.0.0.1.

Model yang tersedia lewat fm serve hanya satu, bernama system. Statusnya masih beta.

03Membangun ChatAFM

fm sebenarnya sudah punya mode chat di terminal (fm chat). Namun, saya ingin antarmuka yang lebih nyaman: riwayat percakapan, jawaban yang tampil bertahap, render Markdown, dan indikator sisa konteks. Hasilnya adalah ChatAFM, GUI chat berbasis browser yang hanya terdiri dari dua file:

  • fm_chat.py, server kecil yang hanya memakai pustaka standar Python. Tugasnya menyajikan halaman dan meneruskan permintaan /v1/* ke fm serve, termasuk respons streaming.
  • index.html, antarmuka chat dengan HTML, CSS, dan JavaScript dalam satu file. Tidak perlu build step dan tidak perlu internet.

Fitur yang tersedia:

  • Percakapan multi-giliran dengan riwayat di sidebar dan tombol New chat.
  • Instruksi sistem yang bisa diubah per percakapan.
  • Jawaban tampil bertahap (streaming), dengan tombol Stop atau tombol Esc.
  • Render Markdown, termasuk tabel dan blok kode dengan tombol Copy.
  • Meteran pemakaian konteks terhadap batas 8.192 token, dengan peringatan di 75% dan 90%.
  • Riwayat tersimpan di browser (localStorage), plus ekspor ke Markdown atau JSON.
  • Pesan galat yang jelas jika fm serve belum berjalan atau port salah.
Mengapa perlu proxy Python? Awalnya saya mengira cukup satu file HTML, karena fm serve mengirim header CORS. Ternyata header itu hanya berlaku untuk permintaan GET. Permintaan chat (POST) dari halaman yang berbeda origin, termasuk file yang dibuka langsung lewat file://, ditolak dengan status 403. Karena itu halaman harus disajikan dari origin yang sama dengan proxy, dan tugas itulah yang dikerjakan fm_chat.py.

04Cara Menjalankan ChatAFM

Kebutuhannya adalah Mac Apple Silicon dengan macOS 27 dan Apple Intelligence yang sudah aktif. Python bawaan macOS (versi 3.9) sudah cukup.

  1. Buka Terminal pertama, lalu jalankan fm serve di foreground. Biarkan jendela ini tetap terbuka. Jangan jalankan di background dan jangan tekan Ctrl-Z.

    fm serve --host 127.0.0.1 --port 8765

  2. Buka Terminal kedua, masuk ke folder ChatAFM, lalu jalankan servernya.

    python3 fm_chat.py --open

  3. Browser akan terbuka di http://localhost:8770. Jika tidak terbuka otomatis, buka alamat itu secara manual.

  4. Untuk berhenti, tekan Ctrl-C di Terminal ChatAFM, lalu di Terminal fm serve.

Port bisa diatur lewat argumen berikut.

05Kelebihan dan Keterbatasan

Kelebihan

  • Privat. Prompt dan jawaban tidak meninggalkan Mac.
  • Gratis tanpa kuota. Tidak ada batas 5 jam atau batas mingguan seperti layanan chat berbayar.
  • Jalan offline. Cocok saat koneksi buruk.
  • Sudah terpasang. Tidak perlu mengunduh model sendiri.
  • API kompatibel OpenAI. Mudah dihubungkan ke aplikasi atau skrip yang sudah ada.
  • Cukup baik dalam bahasa Inggris untuk penjelasan umum, ringkasan, dan contoh kode pendek.

Keterbatasan

  • Bahasa Indonesia lemah. Tidak didukung resmi, jawabannya cenderung terlalu umum dan sering keliru.
  • Akurasi faktual terbatas, bahkan dalam bahasa Inggris.
  • Konteks pendek. Sekitar 8.192 token, jadi percakapan panjang atau dokumen besar cepat penuh.
  • Jeda awal terasa. Butuh 7 sampai 12 detik sebelum teks pertama muncul.
  • Hanya satu model. Tidak ada pilihan model yang lebih besar.
  • Berat di RAM 8 GB bila dipakai bersama banyak aplikasi dan tab browser.

Soal kuota, yang ada hanyalah batas konteks per percakapan. Jika penuh, cukup mulai percakapan baru tanpa perlu menunggu. Kecepatan bisa menurun saat Mac sedang sibuk, tetapi pemakaian tidak pernah diblokir.

Soal memori, saat tidak sedang menjawab, fm serve dan ChatAFM hampir tidak memakan RAM, masing-masing sekitar 2 MB. Namun saat saya memakainya bersama banyak tab browser, swap sempat terpakai sekitar 6 GB dan Mac terasa lambat. Di Mac 8 GB, sebaiknya tutup aplikasi yang tidak perlu sebelum memakai model ini.

06Bahasa Menentukan Kualitas

Temuan paling penting dari uji coba ini adalah pengaruh bahasa. Saya bertanya tentang arsitektur Transformer dengan salah ketik, yaitu transformes, lalu membandingkan hasilnya.

Ada tiga pelajaran dari tabel ini. Pertama, bahasa jawaban jauh lebih berpengaruh daripada bahasa instruksi sistem. Mengganti instruksi sistem ke bahasa Inggris tidak membantu selama jawabannya tetap diminta dalam Bahasa Indonesia. Kedua, pertanyaan juga harus berbahasa Inggris. Pertanyaan berbahasa Indonesia membuat model mengabaikan instruksi untuk menjawab dalam bahasa Inggris. Ketiga, jawaban bahasa Inggris pun tetap perlu dicek. Dalam satu uji, model menyebut lapisan feedforward berfungsi menangkap ketergantungan jarak jauh, padahal itu tugas mekanisme attention.

Jika hasil berbahasa Indonesia tetap dibutuhkan, cara terbaik yang saya temukan adalah dua langkah. Minta jawaban dalam bahasa Inggris terlebih dulu, lalu minta model menerjemahkannya. Hasil terjemahannya tepat topik dan cukup lengkap, meskipun beberapa istilah terdengar kaku, misalnya "memurnikan keluaran lapisan".

Karena temuan ini, antarmuka ChatAFM sengaja saya buat berbahasa Inggris. Instruksi sistem bawaannya pun berbahasa Inggris, dan setiap percakapan baru menampilkan pengingat untuk menulis prompt dalam bahasa Inggris.

07Catatan untuk Developer

Sebelum menulis kode ChatAFM, saya memeriksa perilaku asli fm serve dengan curl dan browser. Ada beberapa perbedaan penting dibanding API OpenAI.

TemuanDampak
Tanpa field stream, respons tetap berupa streaming (SSE)Kirim "stream": false secara eksplisit jika ingin JSON biasa
Galat saat streaming, misalnya konteks penuh, dikirim sebagai event: error dengan status HTTP 200Klien harus membaca nama event SSE, bukan hanya status HTTP
GET mengirim header CORS untuk origin apa pun, tetapi POST ditolak jika Origin: null atau Sec-Fetch-Site bernilai same-site atau cross-siteHalaman web perlu proxy kecil di origin yang sama
stream_options.include_usage didukungPemakaian token bisa dibaca untuk indikator konteks
Ada endpoint GET /health yang melaporkan ketersediaan modelBerguna untuk menampilkan status koneksi
/v1/models hanya berisi system, nama lain ditolak dengan galat 400Belum ada pilihan model lain lewat server ini
fm count-tokens akurat, tetapi butuh 1 sampai 5 detik per panggilanTerlalu lambat untuk dihitung setiap kali mengetik, jadi ChatAFM memakai perkiraan berbasis jumlah karakter

Contoh permintaan non-streaming yang paling sederhana:

curl http://127.0.0.1:8765/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model": "system", "stream": false,
       "messages": [{"role": "user", "content": "Name three primary colors."}]}'

Karena proxy ChatAFM ikut meneruskan permintaan chat, saya menambahkan perlindungan yang sama seperti fm serve. Proxy menolak permintaan POST dari situs lain dan hanya menerima header Host yang mengarah ke loopback. Dengan begitu, proxy tidak membuka celah yang sudah ditutup oleh fm serve.

08Tips dan Ringkasan

  1. Tulis prompt dan instruksi sistem dalam bahasa Inggris.
  2. Pakai untuk tugas ringan, misalnya merangkum, menyusun ulang kalimat, membuat draf, atau menjelaskan konsep umum.
  3. Periksa ulang fakta, angka, dan detail teknis sebelum dipakai.
  4. Mulai percakapan baru saat topik berganti, supaya konteks 8.192 token tidak cepat penuh.
  5. Di Mac dengan RAM 8 GB, tutup aplikasi dan tab yang tidak dipakai.
  6. Jika butuh hasil berbahasa Indonesia, minta jawaban bahasa Inggris dulu, lalu minta terjemahannya.

Secara keseluruhan, Apple Foundation Model di MacBook M1 cocok sebagai asisten ringan yang privat, gratis, dan bisa dipakai offline, asalkan dipakai dalam bahasa Inggris. Untuk riset, topik yang menuntut akurasi tinggi, atau pemakaian dalam Bahasa Indonesia, model ini belum bisa diandalkan.
